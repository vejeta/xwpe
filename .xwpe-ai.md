# Working on xwpe

This is a C editor from 1993, kept alive and extended. Build and test it
before claiming a change works, and leave the code more readable than you
found it.

## Build and run

- Configure once: `autoreconf -fi && ./configure --enable-ai --with-wayland`
- Build: `make -j$(nproc)`
- The one binary is `we`; run it as `./wpe` (terminal) or `./xwpe`
  (graphical). The name selects the mode: `./we` has the programming layer
  off, so use `wpe` for anything involving compiling, debugging or the
  assistant.

## Tests

- C unit tests: `make check`
- Terminal tests: `WPE_BIN=$PWD/wpe tests/.venv/bin/python -m pytest -q tests/<file>.py`
- Sanitizer: `tests/run-tests.sh --asan` builds `we-asan`; run it as `wpe-asan`.
- A new test must fail on the old code before it passes on the new one, and
  it asserts on the file on disk, the screen cells or the trace, never on the
  program being alive.

## Style

- One function, one job, named for the job; the caller reads like prose. No
  inline blocks inside switch cases or if/else chains: extract a function.
- Named constants, never bare numbers in conditions.
- Every new function gets a `/** */` comment that says what the user gains
  and when, not a restatement of the code.
- Indent as the surrounding code does (one space per level in the old files).
- A condition goes outside the call, never a ternary buried in arguments.
- Documentation is part of the change: `docs/chapters/*.texi`, `docs/*.md`
  and `CHANGELOG` (in a user's words) move with the code.

## Do not

- Do not edit files with in-place stream tools (`sed -i`, `perl -i`); use the
  editor's own edits.
- Do not weaken, skip or delete a test to make a suite pass.
- Do not commit or push: leave changes in the working tree for review.
