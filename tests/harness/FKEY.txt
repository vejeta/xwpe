# Tests that press a terminal function key, one pytest node id per line.
#
# Why this list exists: a hosted CI runner's pseudo-terminal does not deliver
# function-key sequences to the editor, although its terminfo is present and
# the smoke check passes, so these tests fail there for the terminal's reason
# and not the code's.  They run and their verdicts are visible, but they do not
# gate the job.  Everything else in the same files does gate, which is why this
# is a list of tests rather than of files: of the ten files that mention a
# function key, only these thirteen tests send one, and the other fifty-one
# tests in them need no special treatment.
#
# How it is used: harness.py takes these out of the `ncurses` layer and makes
# them the whole of the `ncurses-fkey` layer, so run.sh deselects them when it
# gates and runs exactly them when asked for that layer.  A local run of the
# `asan` layer keeps them, because function keys arrive normally here.
#
# Measured 2026-10-19 by reading every mapped test body and every helper in
# those files for an SS3 sequence (F1 to F4, "\033O" + P/Q/R/S) or a CSI one
# (F5 to F12, "\033[" + 11 to 24 + "~"), including the ESC-meta forms.  No
# helper or fixture sends one, so a test not listed here does not press one.
# Add a line when a test starts sending a function key; the drift guard says so
# if a line here stops resolving.
#
# The one entry with no scenario id is test_no_crash_editor_after_resize: it
# shares a file with two mapped scenarios, so the gate would run it, and it
# saves with F2.  It is listed for the deselection, not as coverage.
